# Стиль кода (CRM, React + JS)

## Общее
- Комментарии и объяснения — на русском.
- Код (переменные, функции, компоненты) — на английском.
- Функциональные компоненты + хуки. Без классовых компонентов.

## Именование
- Компоненты: PascalCase (`UserCard.jsx`).
- Хуки: camelCase с префиксом `use` (`useAuth.js`).
- Функции и переменные: camelCase (`fetchUsers`).
- Константы: UPPER_SNAKE_CASE (`API_URL`).
- CSS-классы: kebab-case (`user-card`).

## Структура
- `src/components` — переиспользуемые UI-компоненты.
- `src/pages` — страницы (роуты).
- `src/context` — React Context.
- `api.js` — все запросы к бэкенду. Не делай `fetch` внутри компонентов.

## Запреты
- Не трогай `package-lock.json` и `node_modules`.
- Не добавляй новые зависимости без явного разрешения.
- Не используй `any` (если перейдёте на TS).

## Навигация
- Перед началом работы прочитай `docs/project_map.md`, чтобы понять структуру.
- Если задача касается API — прочитай `src/api.js`.
- Если задача касается страницы — найди её в `src/pages`.

## Журнал изменений
- После каждого успешного изменения файлов (после нажатия Accept) **обязательно** обнови `docs/CHANGELOG_AGENT.md`.
- Записывай туда: дату, какой файл изменён, что именно сделано (одна строка).
- В начале каждой новой задачи **сначала прочитай** `docs/CHANGELOG_AGENT.md`, чтобы понять, что уже было сделано.
## Обновление документации
- Если ты создаёшь НОВЫЙ файл или папку (компонент, страницу, утилиту), ты **обязан** добавить путь к нему в `docs/project_map.md`.
- Если ты удаляешь файл, удали его путь из `docs/project_map.md`.
- Если ты переименовываешь файл, обнови путь в `docs/project_map.md`.
- После любых изменений в структуре проекта (создание/удаление/переименование) обязательно обнови `docs/project_map.md`, чтобы он всегда отражал актуальное состояние.
